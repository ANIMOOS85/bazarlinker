# بازار لینکَر — Django

نسخه فارسی و راست‌چین راهنمای محلی فروشگاه‌ها با Django، SQLite، قالب‌های HTML، CSS و JavaScript. این پروژه برای معرفی محصول و فروشگاه و ارتباط مستقیم با فروشنده ساخته شده است؛ سبد خرید و درگاه پرداخت آنلاین ندارد.

## اجرای محلی در ویندوز

1. Python 3.11 یا جدیدتر را نصب کن و گزینه Add Python to PATH را فعال کن.
2. ZIP را استخراج کن.
3. روی `run.bat` دوبار کلیک کن. اسکریپت محیط مجازی را می‌سازد، وابستگی‌ها را نصب می‌کند، مهاجرت‌های موجود را اجرا می‌کند و طرح‌های اولیه را می‌سازد.
4. اگر مدیر ارشد در دیتابیس وجود نداشته باشد، در اجرای اولیه از تو خواسته می‌شود نام کاربری، ایمیل و رمز مدیر را خودت وارد کنی؛ هیچ رمز پیش‌فرض ثابتی در پروژه وجود ندارد.
5. سایت: http://127.0.0.1:8000/ — پنل مدیر: http://127.0.0.1:8000/manage/ — پنل Django: http://127.0.0.1:8000/django-admin/

اگر لازم بود مدیر را جداگانه بسازی، در پوشه پروژه اجرا کن:

```bash
python manage.py createsuperuser
```

## اجرای محلی در Linux/macOS

اسکریپت `run.sh` را اجرا کن. برای اجرای دستی دستورات مدیریتی، ابتدا محیط مجازی را فعال کن.

## امنیت و انتشار روی هاست

تنظیمات توسعه و انتشار عمداً از هم جدا شده‌اند. فایل `.env.example` را با نام `.env` کپی کن و قبل از انتشار، مقدارهای واقعی را وارد کن:

- `DJANGO_SECRET_KEY`: یک مقدار طولانی و تصادفی که فقط مخصوص همین سایت باشد.
- `DJANGO_DEBUG=0`: در محیط عمومی باید خاموش باشد.
- `DJANGO_ALLOWED_HOSTS`: دامنه واقعی سایت، بدون `https://` و بدون مسیر.
- `DJANGO_SECURE_SSL_REDIRECT=1` و `DJANGO_HSTS_SECONDS=31536000` فقط هنگامی فعال شوند که HTTPS در هاست درست تنظیم شده باشد.

برای تولید یک کلید می‌توانی از دستور زیر استفاده کنی:

```bash
python -c "import secrets; print(secrets.token_urlsafe(64))"
```

متغیرهای محیطی تعریف‌شده در هاست بر فایل `.env` اولویت دارند. در حالت DEBUG خاموش، برنامه بدون `DJANGO_SECRET_KEY` معتبر بالا نمی‌آید. فایل `.env` را به مخزن Git ارسال نکن.

## تغییرات و امکانات اصلاح‌شده

- صفحه 404 اختصاصی هماهنگ با طراحی بازار لینکَر، برای مسیرهای ناموجود و شناسه‌های نامعتبر؛ صفحه خطا حتی در حالت توسعه نیز نمایش داده می‌شود.
- صفحه 500 اختصاصی برای خطاهای سمت سرور در محیط انتشار.
- حذف ساخت مدیر با رمز ثابت و نمایش اطلاعات ورود پیش‌فرض از README.
- اصلاح popup نقشه برای نمایش امن نام و اطلاعات فروشگاه، بدون چسباندن داده فروشنده به HTML.
- اعتبارسنجی لینک‌های خارجی با HTTPS، شماره تماس و مختصات جغرافیایی.
- بررسی محتوای واقعی فایل تصویری، محدودیت حجم و ابعاد؛ فایل‌هایی که صرفاً MIME جعلی دارند پذیرفته نمی‌شوند.
- نگهداری رسید پرداخت خارج از پوشه عمومی `media/` و ارائه آن فقط به مدیر واردشده؛ مهاجرت جدید تلاش می‌کند رسیدهای قبلی را نیز به محل خصوصی منتقل کند.
- استفاده از اعتبارسنج‌های استاندارد رمز عبور Django هنگام ثبت‌نام.
- خروج فقط با درخواست POST، جلوگیری از ثبت چند درخواست اشتراک در انتظار و جلوگیری از بررسی مجدد اشتراک یا معرفی.
- محاسبه اشتراک بر اساس ماه تقویمی و تمدید از پایان اشتراک فعال فعلی.
- تأیید جایزه معرفی تنها پس از بررسی فروشگاه فعال و آگهی منتشرشده.
- امکان ویرایش آگهی و کنترل وضعیت انتشار آگهی از پنل مدیر.
- نمایش اطلاعات کارت‌به‌کارت در پنل فروشنده و اصلاح شمارنده معرفی‌های موفق.
- مرتب‌سازی نتایج نقشه به‌گونه‌ای که فروشگاه‌های دارای آگهی منطبق با فیلتر فعلی در اولویت باشند.

## آزمایش‌ها

برای اجرای تست‌ها پس از فعال‌کردن محیط مجازی، در Windows CMD ابتدا تنظیمات توسعه را برای همان پنجره تعریف کن:

```bat
set DJANGO_DEBUG=1
set DJANGO_SECRET_KEY=django-insecure-local-development-only-change-before-deployment
set DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1
python manage.py test market
```

در Linux/macOS همین متغیرها را با `export` تعریف کن. اگر فایل `.env` داری، مقدارهای داخل آن استفاده می‌شوند مگر اینکه متغیر متناظر از قبل در محیط تعریف شده باشد.

در این پروژه از SQLite استفاده می‌شود؛ پیش از ارتقا یا استقرار، از `db.sqlite3` و پوشه `media/` نسخه پشتیبان تهیه کن. نقشه برای بارگذاری کاشی‌های OpenStreetMap و کتابخانه Leaflet به اینترنت نیاز دارد.


## استقرار دمو روی Render

این بسته با `render.yaml`، PostgreSQL، WhiteNoise و Gunicorn آماده شده است.

1. پروژه را روی GitHub در یک مخزن جدید Push کنید؛ `.venv`، `.env`، `db.sqlite3`، `media/` و `private_uploads/` به خاطر `.gitignore` وارد مخزن نمی‌شوند.
2. در Render از مسیر **New → Blueprint** مخزن GitHub را انتخاب کنید.
3. هنگام ساخت Blueprint مقدارهای `DJANGO_SUPERUSER_USERNAME`، `DJANGO_SUPERUSER_EMAIL` و `DJANGO_SUPERUSER_PASSWORD` را وارد کنید. رمز را قوی و یکتا انتخاب کنید. ساخت مدیر فقط اگر آن نام کاربری از قبل وجود نداشته باشد انجام می‌شود.
4. بعد از پایان Deploy، از دامنه‌ای که Render می‌دهد سایت را باز کنید. برای تنظیم اطلاعات کارت و مدیریت، با حساب مدیر وارد `/manage/` یا `/django-admin/` شوید.

**محدودیت پلن رایگان:** سرویس وب بعد از ۱۵ دقیقه بی‌ترافیکی می‌خوابد و درخواست بعدی ممکن است حدود یک دقیقه طول بکشد. فایل‌های ذخیره‌شده روی دیسک سرویس (از جمله تصاویر آگهی و رسید پرداخت) پایدار نیستند و ممکن است با خواب/راه‌اندازی مجدد یا Deploy از بین بروند. دیتابیس رایگان Render PostgreSQL نیز ۳۰ روز پس از ساخته‌شدن منقضی می‌شود؛ برای دمو کوتاه‌مدت مناسب است، نه داده واقعی یا تولید.
